# RetailX Data Orchestration & Lakehouse Platform

RetailX Data Orchestration & Lakehouse Platform is an end-to-end Data Engineering project designed to demonstrate a modern retail data pipeline using Dagster, Apache Spark, MinIO, Apache Iceberg, Dremio, Docker, Python, SQL, Git, and GitHub. The platform takes raw retail CSV data containing customers, products, orders, payments, and stores, orchestrates the complete data workflow through Dagster, stores raw data in an S3-compatible MinIO Bronze layer, processes and transforms the data using Apache Spark, creates Silver and Gold analytical datasets, stores the processed datasets as Apache Iceberg lakehouse tables, and exposes the final data for SQL analytics through Dremio. The overall architecture follows the Medallion Architecture pattern: Raw Data → Dagster → Bronze → Spark → Silver → Gold → Iceberg → Dremio → Analytics. The source datasets include customers with customer_id, name, and city; products with product_id, product_name, category, and price; orders with order_id, customer_id, product_id, quantity, and order_date; payments with payment_id, order_id, payment_method, payment_status, and amount; and stores with store_id, store_name, city, and state. The raw project structure contains data/raw/customers.csv, data/raw/products/products.csv, data/raw/orders/orders.csv, data/raw/payments/payments.csv, and data/raw/stores/stores.csv. The Bronze layer is implemented on MinIO using an S3-compatible interface and contains the raw datasets under the retailx bucket, including bronze/customers.csv, bronze/products.csv, bronze/orders.csv, and bronze/payments.csv. Bronze is used to preserve the incoming data before transformation and provides a reliable starting point for downstream processing and reprocessing. Dagster acts as the orchestration layer and manages assets, dependencies, execution, schedules, retries, and data quality checks. The project contains Dagster assets for customers, products, orders, payments, stores, Bronze datasets, Silver datasets, Gold datasets, Spark processing, Iceberg processing, MinIO connectivity, and quality validation. The Spark pipeline contains spark_silver_customers, spark_silver_remaining, and spark_gold_sales assets, with the Gold processing depending on the successful completion of the Silver processing. Spark execution is configured with retries to improve pipeline reliability. A daily Dagster schedule is configured for the Spark pipeline at 09:00 Asia/Kolkata. Apache Spark 3.5.6 is used for distributed data processing and reads the Bronze datasets from MinIO through S3-compatible paths. The customers Silver job reads s3a://retailx/bronze/customers.csv and writes the transformed customer dataset to s3a://retailx/silver/customers. The remaining Silver job processes products, orders, and payments and writes them to s3a://retailx/silver/products, s3a://retailx/silver/orders, and s3a://retailx/silver/payments. The Gold processing job joins customers, products, orders, and payments to create a business-ready sales dataset. The Gold layer contains sales, daily_sales, and category_sales datasets. The main Gold Sales dataset contains 15 records and a total sales value of 199,800. The Gold Sales data combines order information, customer information, product information, quantity, unit price, total amount, payment method, and payment status. The daily sales analytics contains sales for 2026-09-01 through 2026-09-08, with daily revenue of 58,000 on September 1, 10,900 on September 2, 12,500 on September 3, 24,600 on September 4, 2,300 on September 5, 60,000 on September 6, 14,500 on September 7, and 17,000 on September 8, resulting in total revenue of 199,800. Category-level analysis contains Electronics with 8 order lines, 15 items, and 151,400 in sales; Furniture with 4 order lines, 5 items, and 45,500 in sales; Accessories with 1 order line, 1 item, and 1,800 in sales; and Stationery with 2 order lines, 15 items, and 1,100 in sales. Apache Iceberg is used as the lakehouse table format. The Iceberg Hadoop catalog is configured with the warehouse located at s3a://retailx/iceberg/warehouse. The Iceberg Silver pipeline creates customers, products, orders, and payments tables under the retailx namespace, while the Gold Iceberg pipeline creates the retailx.sales table. The Gold Iceberg sales table contains order_id, order_date, customer_id, customer_name, customer_city, product_id, product_name, category, quantity, unit_price, total_amount, payment_method, and payment_status. Iceberg provides table metadata, snapshots, schema management, reliable table operations, and lakehouse table organization while allowing compute and storage to remain separated. Dremio is used as the SQL analytics layer and connects to MinIO to query the Iceberg tables. The Dremio source is configured against the S3-compatible MinIO storage and successfully exposes the Iceberg warehouse containing customers, orders, payments, products, and sales tables. SQL queries can be executed in Dremio against the Gold Sales dataset for business analytics such as total revenue, category sales, daily sales, order analysis, customer analysis, and product performance. The project also implements automated data quality validation. The customer quality check verifies that customer_id is present and that customer name and city are not empty. The Gold Sales quality check verifies that the dataset contains records, order IDs are not null, product IDs are not null, customer IDs are not null, and sales amounts are not negative. Successful validation produces a QUALITY CHECK PASSED result. The project uses Docker to run the infrastructure components including MinIO, Spark Master, Spark Worker, and Dremio. The MinIO container is named retailx-minio and exposes the API through port 19020 and the MinIO console through port 19021. The Spark Master is named retailx-spark and exposes the Spark UI through port 18080 and Spark Master communication through port 17077. The Spark Worker is named retailx-spark-worker and connects to the Spark Master. Dremio runs as retailx-dremio and exposes its interface through port 9047. The Dagster development environment runs on port 3000. The project uses Python 3.11+, Apache Spark 3.5.6, Java, Docker Desktop, MinIO, Apache Iceberg 1.10.0, Dagster 1.13.24, Dremio, SQL, Git, GitHub, and PowerShell on Windows. The virtual environment is located at C:\retailx-data-orchestration.venv. The Spark jobs are located inside the spark_jobs directory. The main Dagster definitions file is retailx_orchestration\retailx_orchestration\definitions.py. The local Dagster IO manager stores runtime asset artifacts under data/dagster_storage, and this directory is excluded from Git using .gitignore.
